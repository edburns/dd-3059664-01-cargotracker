Resolved decisions: the editor is a serializable CDI `@Named @ViewScoped` bean. It communicates only through `BookingServiceFacade` and `CargoRoute`. On load it parses the DTO's date-only display value with a per-load `new SimpleDateFormat("MM/dd/yyyy")`; no shared mutable formatter or DTO expansion is allowed. A malformed value must surface clearly. Submission requires a non-null `Date`, delegates through the facade, and closes with `"DONE"` only after success. No future-date, after-old-deadline, or itinerary chronology rule is added.

Research established that the existing formatted arrival deadline begins with `MM/dd/yyyy` and that the date-only representation is the established editor value. Tests compile under the Open Liberty build even though historical Arquillian execution remains remote-Payara-specific. Implement from production contracts, not research/spike source code.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDate.java`

Use this required shape:

```java
@Named
@ViewScoped
public class ChangeArrivalDeadlineDate implements Serializable {
    private static final long serialVersionUID = 1L;

    private String trackingId;
    private CargoRoute cargo;
    private Date arrivalDeadlineDate;

    @Inject
    private BookingServiceFacade bookingServiceFacade;
}
```

Provide:

- `getTrackingId()` and `setTrackingId(String)`;
- `getCargo()`;
- `getArrivalDeadlineDate()` and `setArrivalDeadlineDate(Date)`;
- `load()`;
- `changeArrivalDeadline()`.

`load()` must call `bookingServiceFacade.loadCargoForRouting(trackingId)`, store the returned `CargoRoute`, parse `cargo.getArrivalDeadlineDate()` with a new per-load `SimpleDateFormat("MM/dd/yyyy")`, and store the result. Do not access domain objects or repositories. Handle parse failure using the application's established JSF error mechanism; do not swallow it, print a stack trace, or convert it to null.

`changeArrivalDeadline()` must reject a null selected date with clear JSF validation/error behavior, call `bookingServiceFacade.changeDeadline(trackingId, arrivalDeadlineDate)`, and only after successful return call:

```java
PrimeFaces.current().dialog().closeDynamic("DONE");
```

Do not close the dialog when validation or facade work fails.

If practical with existing infrastructure, add a container-free JUnit test using a hand-written facade fake. It must prove correct tracking-ID loading, `MM/dd/yyyy` conversion, exact submit delegation, surfaced malformed DTO input, and null-date rejection. Keep production injection idiomatic; use existing test-access patterns rather than weakening encapsulation solely for tests.

## Completion gates

- The bean is serializable with `serialVersionUID = 1L`, CDI `@Named`, JSF `@ViewScoped`, and injected `BookingServiceFacade`.
- Imports remain in the historical `javax.*` namespace.
- The bean references facade DTOs only and contains no repository/domain access.
- Parsing uses a non-shared formatter and failure cannot become a successful null submission.
- Null dates are rejected; successful calls close with `"DONE"`; failed calls do not close.
- `./mvnw clean package -Popenliberty` succeeds on JDK 17 and all prior task sources remain compiling.
